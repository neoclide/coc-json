# coc-json

JSON/JSONC language support for coc.nvim on Vim and Neovim.
Upstream: VS Code `json-language-features`, available locally at
`/Users/chemzqm/lib/vscode/extensions/json-language-features`.

## Workflow

- Use `coc-workflow` for maintenance and `coc-vscode-sync` before upstream ports.
  Follow their detailed procedures for context, ownership, review, and validation.
- Use npm (`package-lock.json`). Existing checks: `npm run lint`,
  `npm run build`, and `npm test` (coc-test). For editor-specific coverage, use
  `npm run test:integration:nvim` and `npm run test:integration:vim`.

## Project boundaries

- `src/` contains the Coc client and UI integration; `server/` contains the
  language server. `lib/` is generated by `esbuild.js`; do not edit it by hand.
- Preserve Coc-specific behavior, public commands, configuration keys/defaults,
  filetypes, activation, cancellation/disposal, and language-server startup.
  Coc compatibility takes priority over textual similarity with upstream.
- Verify API semantics against the installed coc.nvim types and implementation.
  Use Coc-native APIs; do not add a `vscode` runtime dependency or unsupported
  VS Code workbench features.
- Port upstream changes as small semantic patches, preserving Coc adaptations.
  Do not replace source files or `package.json` wholesale with upstream versions.

## Documentation

- Record user-visible changes under the current version in `history.md`,
  following the existing style.
- For upstream syncs, also update `migrate.md` with the revision range, ported
  commits, and intentionally skipped changes with reasons.
